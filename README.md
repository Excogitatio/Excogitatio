I'm a developer interested in how software works beneath the surface — from user-facing applications and backend architecture to low-level systems, security tooling, and database internals.

I work across multiple layers of the stack, choosing technologies for their capabilities rather than following a single ecosystem.

My current interests include:

- **Systems programming** — exploring performance, memory, concurrency, and low-level architecture with Rust and Zig.
- **Full-stack development** — building applications that connect thoughtful interfaces with reliable backend systems.
- **Security engineering** — developing tools for security research, analysis, and defensive automation.
- **Database infrastructure** — exploring PostgreSQL integration, native interfaces, and WebAssembly-compatible libraries.
- **Minecraft infrastructure** — developing plugins for PumpkinMC and exploring extensible server-side systems.

I value clean architecture, deliberate engineering, and understanding the problem before writing the solution.

## `03` — Current Work

### ◈ PostgreSQL · Zig · WebAssembly

**A PostgreSQL library targeting `wasm32-wasi`**

Exploring the intersection of Zig, PostgreSQL, and WebAssembly through a library designed around the `wasm32-wasi` target.

Areas of interest include:

- PostgreSQL integration and protocol-level interaction.
- Zig's explicit memory management and cross-compilation capabilities.
- WASI compatibility and portability constraints.
- Small, predictable interfaces between systems.

*An exploration of database infrastructure beyond conventional native targets.*

> Repository and implementation details will be documented as the project develops.

### ◈ PumpkinMC · Server Plugins

**Extending Minecraft server infrastructure**

Building plugins for PumpkinMC, with an interest in server-side functionality, extensibility, and maintainable plugin architecture.

The goal: useful tools and systems that integrate cleanly into the server environment.

### ◈ Security Engineering

**Tools for understanding and securing software**

Developing security-focused utilities and exploring the engineering behind reliable security tooling.

Areas of interest include:

- Defensive security automation.
- System inspection and analysis.
- Protocols and application security.
- Developer tools that make complex systems easier to understand.

## `04` — Engineering Philosophy

<div align="center">

| Principle | Approach |
|:---|:---|
| **Precision** | Prefer explicit, understandable implementations. |
| **Performance** | Understand the cost of abstractions. |
| **Security** | Treat trust boundaries as engineering decisions. |
| **Portability** | Design with environments and constraints in mind. |
| **Craft** | Build software that is worth maintaining. |

</div>

I don't believe good engineering is about using the most complicated technology available.

It's about understanding the constraints, selecting the right tools, and building something that solves the problem well.
